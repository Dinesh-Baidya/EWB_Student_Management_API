# Student Management API — EWB Internship Assignment

A modular Python backend for managing student records with FastAPI, SQLite, and SQLAlchemy. It includes CRUD endpoints, filtering, validation, missing-record handling, and an optional local Ollama AI endpoint.

## Requirements

- Python 3.11 recommended
- Git (for GitHub submission)
- Ollama only if you want to use the optional AI endpoint

## Setup on Windows PowerShell

```powershell
cd C:\path\to\your\project
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirement.txt
Copy-Item .env.example .env
uvicorn main:app --reload
```

If PowerShell blocks activation, you can run the server using `venv\Scripts\python.exe -m uvicorn main:app --reload` after installing dependencies.

Open Swagger UI at http://127.0.0.1:8000/docs and ReDoc at http://127.0.0.1:8000/redoc.

The SQLite database is created automatically. Existing SQLite databases are kept; the app adds `email` and `phone` columns if they are missing. Existing records can have blank contact fields, but new student records must include at least one of email or phone.

## Student fields

- `id`: unique ID generated by the database
- `student_name`: required
- `student_class`: required
- `student_section`: required
- `student_dob`: required, ISO date such as `2005-04-23`
- `student_sub`: optional
- `email`: optional, valid email address
- `phone`: optional, at least 7 characters
- At least one of `email` or `phone` is required when creating a student.

## CRUD endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/students/` | Create a student |
| GET | `/students/` | List students, optionally filter |
| GET | `/students/{student_id}` | Retrieve one student |
| PUT | `/students/{student_id}` | Update a student's fields |
| DELETE | `/students/{student_id}` | Delete a student |
| POST | `/ai/query-students` | Optional natural-language query using Ollama |

### Create student example

```json
{
  "student_name": "Dinesh",
  "student_class": "B.Tech CSE AI/ML",
  "student_section": "D",
  "student_dob": "2005-04-23",
  "student_sub": "Python",
  "email": "dinesh.demo@example.com",
  "phone": "9876543210"
}
```

Use dummy information only. Do not upload real student personal data to a public repository.

### Filter students

Examples:

- `GET /students/?name=Dinesh`
- `GET /students/?student_class=B.Tech`
- `GET /students/?section=D`
- `GET /students/?born_after=2005-01-01`
- Combine filters, e.g. `GET /students/?name=Din&section=D&skip=0&limit=20`

### Missing records and validation

- A nonexistent student ID returns HTTP `404`.
- Invalid input returns HTTP `422`.
- Duplicate email returns HTTP `409`.
- List pagination limits are validated.

## Optional Ollama AI

1. Install Ollama from https://ollama.com/.
2. In PowerShell, download the model once:

```powershell
ollama pull llama3.2:1b
```

3. Make sure Ollama is running.
4. Start FastAPI as above.
5. In Swagger, execute `POST /ai/query-students`:

```json
{
  "question": "How many students are there?"
}
```

Other example:

```json
{
  "question": "List students born after 2005"
}
```

The AI endpoint reads records through the same SQLAlchemy database session as the CRUD API. Simple count questions are calculated directly from database records. For other questions, retrieved records are supplied as context to the local model. The model is not allowed to execute SQL.

If Ollama is unavailable, the AI endpoint returns HTTP `503` with a diagnostic message. Core CRUD functionality does not require Ollama.
